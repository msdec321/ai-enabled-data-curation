# AutoDQA agent on Bedrock AgentCore Runtime.
# No pyodbc / DB drivers: tools are remote via the AgentCore Gateway, so the
# runtime image stays light.
#
# THE LANGCHAIN/MCP STACK IS EXACT-PINNED ON PURPOSE. These packages are tightly
# coupled and the image builds in the cloud (CodeBuild), so unpinned ranges mean every
# deploy re-resolves and can land on a combination that has never been tested. That is
# what broke the 2026-07-30 deploy: langchain-mcp-adapters was `>=0.1`, the build took a
# newer release whose callbacks module does
#     from mcp.shared.context import RequestContext
# and the transitively-resolved `mcp` did not export it. The container died on import of
# gateway_tools, so the Runtime never started and every invoke returned
# HTTP 424 "An error occurred when starting the runtime" — with the real cause only
# visible in CloudWatch.
#
# `mcp` is pinned EXPLICITLY even though it is only a transitive dependency of
# langchain-mcp-adapters. Leaving it implicit is precisely what allowed the mismatch.
#
# These are the versions verified working locally (test_gateway.py plus a live
# gateway round trip of all five ETL tools). Bump them deliberately, together, and
# re-run that round trip — not by widening a range.
